# DDR Word templates (Approach D)

Generated reports are Word (.docx) with 6AM Advisory Limited branding (logo from `public/logo.png`).

## Workflow
1. Generate DOCX (company: `/api/docgen` type=DDR; person: `/api/docgen/person`)
2. Download → print → wet-ink sign Part 4 Approver Signature
3. Scan/photo → Upload signed (PDF/JPG/PNG) as document type `DDR` or `PERSON_DDR`

## Implementation
- Runtime renderer: `src/lib/docgen/ddr-docx.ts` (docx library; bilingual tables; print-safe gray headers)
- Entry points: `generateDDR` / `generatePersonDDR` in `src/lib/docgen/ddr.ts` (delegate to DOCX)
- Optional future: place `templates/DDR-Company.docx` / `DDR-Person.docx` with docxtemplater `{tags}` (same pattern as KYC.docx)

Place your official DDR Word layout notes here. Runtime reports are generated by `src/lib/docgen/ddr-docx.ts`.

## Part 1.3 Adverse media (manual)
- Method: Manual review (not Google CSE)
- Pass/Fail: 通過 CLEAR / 不通過 HIT / 未完成
- Completed at + Performed by + Manual notes
- Supporting files table: `KYC_ADVERSE_MEDIA` file name + uploaded at (or「沒有搜索到相關信息 / No related information found」)
- Company DDR: one block per screening subject
- Person DDR: one block for the individual; also repeated under 2.4 with supporting list
